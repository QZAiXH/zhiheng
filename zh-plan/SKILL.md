# 制定可审阅计划

输入为请求、已有授权和项目事实，输出为与任务规模相称的计划及仍需决定的问题。独立调用只制定计划；接收 `zh` 交接时沿用已有决定，不重问。

先查看相关代码和规范，区分已核实事实、假设与建议。只追问会影响下一步实施的决定；从仓库能找到的事实不交给用户回答。复杂度依据不确定性、依赖、影响和可验证性，而非文件数量。尚不能细化的范围保留为未定事项，不能删除或假装已经决定。

开发前将计划直接展示在对话，不只写文件、给链接或以零散进度代替；这是技能流程，不声称自动切换宿主原生 Plan 模式。复杂任务在调查和必要澄清后集中展示下列完整内容，供用户审阅；小任务可合并为几行：

| 内容 | 所需信息 |
| --- | --- |
| 目标与范围 | 可观察的结果、边界及确有必要说明的不包含项 |
| 已核实现状 | 模块、已有能力、约束和问题依据，区分假设 |
| 实施步骤 | 已知文件/模块、顺序、依赖和各步产物 |
| 执行安排 | 小任务主会话或复杂任务执行子 agent 的职责、任务边界、独立上下文 |
| 模型建议 | 委派角色的具体可用型号、推理强度及依据，用户可覆盖 |
| 验收方法 | 完成条件、适当检查和独立审查重点 |
| 交付方式 | 目标分支、worktree、合并清理及已有远端授权 |
| 风险与待定 | 真实取舍、环境限制、未决事项 |

切片按可独立验证的行为和真正依赖划分，不固定按文件/层拆分；广泛迁移可采用兼容扩展、分批迁移、最后收缩，避免要求每个中间步骤都虚假通过。小任务不必建立复杂任务图。模型建议遵循 [委派规则](../zh/references/delegation.md)。

涉及页面或关键业务交互时，按 [前端预览与验收](../zh-implement/references/frontend-preview.md) 在计划中列出预览与正式实现阶段：已有设计依据、要展示的页面/操作/状态/设备、仍待确认的取舍及浏览器验收方法；可简化时记录具体依据和覆盖范围。文字计划或业务规则答复不替代尚未展示的交互确认。独立计划调用只安排这些工作，不编写原型；需要可运行原型时先明确其执行授权，由 `zh` 衔接 `zh-implement`，沿用已建立的有效授权。

小而明确且已授权的任务简要展示后继续；复杂任务未展示完整计划、未解决影响执行的决定或尚缺必要确认时，不启动依赖该计划的开发与委派。明确要求实施同一方案、已有有效计划决定时沿用，不设固定批准口令或重复确认。答复业务规则只确认答复所涉及的决定，不推定用户审阅过尚未展示的计划。计划修订不自动批准实施；实质改变范围、架构或验收时说明差异、影响，保留未变决定并取得受影响部分所需确认。只讨论/只计划的请求留在该范围。

完整计划和后续变化按 [记录规则](../zh/references/records.md) 保存。无需用户阅读执行 JSON、完整子 agent 提示词或所有底层命令。不要发布到远端 tracker，除非本次明确授权。
