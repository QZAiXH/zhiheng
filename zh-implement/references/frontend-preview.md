# 前端预览、确认与浏览器验收

供 `zh` 衔接阶段、`zh-plan` 安排预览、`zh-implement` 制作与实现、`zh-review` 对照验收时按需读取。本文件是前端特殊流程的维护位置；授权、worktree、独立审查仍使用集合既有规则，不新增技能或状态系统。

## 选择流程深度

新页面、布局调整或关键业务交互变化默认先讨论需求，再提供可操作预览，取得具体设计确认后正式开发，最后对照验收。新增开关、跨页面只读行为或新状态等关键交互也适用，即使控件、样式或通用弹窗可以复用。先明确本次要判断的是视觉结构、操作与状态，还是两者；只覆盖相关页面、操作路径、状态和设备，不要求全站原型。

小型样式修复、已有明确设计稿或复用已确认业务交互时，可以直接开发后展示效果，记录设计依据、覆盖范围及简化理由。组件、样式或弹窗的复用只证明表现方式有基础，不证明新增业务操作、状态或跨页面行为已获确认；局部设计稿也不覆盖未明确的关键行为。用户明确要求预览时按要求做，已有效确认的相同范围不重复确认。

仅讨论或独立制定计划不授权写原型代码。已有请求涵盖原型/开发时直接承接，不为新增阶段重复询问执行权限；设计确认仍以实际展示的产物为准。仓库原型在任务 worktree 中制作，可与正式实现共用该 worktree。

## 制作可操作预览

- **放在真实页面语境中**：优先复用组件库、视觉规范、路由和邻近页面的导航、数据形态与内容密度。适合时在现有页面的开发预览入口展示；全新页面才按项目惯例建明显标记的原型入口，不为了演示重建应用架构。不要让未经验证的演示操作触发真实业务写入。
- **让原型回答设计问题**：视觉取舍尚不明确时可以做结构或信息层级不同的少量方案；已有方向时单方案即可。不强制三个方案或固定切换栏。状态/交互问题可用简单 HTML 或项目组件制作能点击操作、看到状态变化和重置的演示，优先展示能区分取舍的场景。
- **覆盖相关行为**：按需求呈现页面结构、主要入口与跳转、弹窗、表单反馈，以及相关加载、空数据、错误状态；涉及移动端时展示对应布局。使用用户领域语言解释结果，避免把调试 JSON 当作用户流程。
- **明确演示边界**：可用模拟数据、内存状态和桩接口；在预览和交接中说明哪些操作是演示、哪些尚未接入真实功能。真实读取也需在已有权限内，数据库或其他外部副作用不能从“制作预览”推导授权。
- **易于打开与复现**：提供实际可访问的地址/文件及必要的启动方式、路由或方案参数和简短操作步骤；先自行打开并操作关键路径，核实提供的入口。远程环境的 `localhost` 不一定是用户的浏览器，不能把未打通的地址宣称为用户可访问，也不为分享擅自部署或开公网服务。

原型精度以能判断本次取舍为准，不提前建设无关生产功能。按风险做足以发现演示失效的检查，既不机械建立完整测试体系，也不禁止有价值的验证。静态图适合讨论视觉方向；有交互的任务需要可操作原型，文字计划和截图不能代替实际操作。

## 展示、确认与正式实现

先交付可审阅预览，再针对布局和主要交互取得具体确认。记录用户针对哪个版本、哪些范围的结论和反馈；业务规则问答、“计划可以”、未回复、只确认某个局部都不能推成整个预览通过。不要让等待时长变成确认。外层可继续不依赖未定取舍的已授权工作，需要该确认的正式实现保持待定。

根据反馈修改受影响部分并再次展示；其余仍有效的决定沿用。用户确认建立设计依据，不扩大需求或授予远端发布权限；若原请求只包含原型，正式实现仍需有对应授权。环境无法提供可操作预览时说明限制，静态图/交互说明可用于继续讨论，但未实际展示或操作的部分保持待验证。

有设计依据和已有开发授权后，按确认的布局与交互接入真实数据、接口及业务逻辑，补齐正式状态处理。可以复用原型中的合适部分，但必须检查其正式质量；演示的成功提示不是后端、持久化或完整业务成功。清除或隔离原型切换器、桩数据和仅演示入口，按项目约定处理，不让其意外成为正式功能。

实现约束使已确认交互需要实质变化时，说明原因、影响和建议，更新受影响预览并确认变化范围。普通实现细节和不改变已确认效果的修复继续推进，不重新审批整份设计。

## 记录与恢复

在 [同一任务记录](../../zh/references/records.md) 中按任务需要保存：当前阶段；设计问题和覆盖范围；预览入口、文件/版本及启动方式；模拟与真实行为边界；用户实际确认的版本、范围和依据；反馈、未决事项与下一步；正式候选及浏览器证据指针。多个方案时记清选择或组合了哪些部分。

保留可恢复的原型源文件或明确提交引用，必要时附截图与交互说明；临时 URL 只是入口，不是唯一证据。可在当前 worktree 中迭代，无须另建原型分支；移除原型或清理 worktree 前，把已确认版本保存在能继续定位的提交/持久证据路径，并在记录中引用。原型版本与正式候选分别标识。

恢复时核对当前产物、完整已确认范围、反馈和未定事项，不把最新反馈覆盖成整个任务、不将尚未确认的版本替换已确认依据。给独立审查者传这些原始材料及必要业务决定，不传执行聊天或自评。

## 正式候选的浏览器验收

使用宿主可用的真实浏览器控制、项目现有浏览器测试等能力打开正式候选，实际执行主要流程，并对照确认的预览/设计依据核对布局与交互。工具按当前环境选择，不依赖运行时下载上游技能，也不固定要求某个浏览器插件。

检查与实际风险匹配：入口与跳转、表单有效/无效反馈、弹窗打开/关闭、相关加载/空/错误路径、需要支持的设备尺寸；键盘或其他可访问性行为在相关规范或任务范围内验证。涉及保存、提交或其他真实功能时，通过已授权的本地/测试环境核实实际请求和用户可见结果；只看到模拟成功提示不能证明功能实现。

保留原始操作记录：候选提交/内容与运行实例的对应关系、环境与启动配置、使用真实接口还是模拟接口、实际浏览器路径/步骤、视口或设备范围、观察结果与限制。必要时附截图、控制台或请求错误证据；截图帮助检查视觉，但不能单独证明操作和数据行为。

结合项目必需构建、类型检查或已有测试。独立审查按条件读取原始证据，必要时针对性复查；浏览器无法运行、实例对应版本不明或关键真实路径受阻时，明确标为无法验证并按现有验收规则处理，不能用构建通过或原型确认替代。变更导致证据失效时补受影响检查，不无理由重做全部已通过操作。
