# 隔离维护案例输入

两次使用反馈指向同一缺陷：某技能收到“只审查这个差异”时把审查报告当成被审成果的通过证明；另一次收到“核对验收条件”时只列出变更文件。原始使用项目、版本、请求和观察分别留在维护任务记录。相邻请求是“请总结这份报告”，不应触发审查或验收技能。

候选改动只能修正相应职责边界。评估侧保存可观察标准：审查任务可完成且被审成果失败；验收需逐项处理未执行与过期证据；相邻总结请求不触发；已有正常审查保持。对比旧版、候选版使用同一输入和可比工具与模型设置，记录真实产物和时间。

退步候选：在描述中写“每次总结代码都必须做验收”，会误触发相邻请求。候选即使修复原问题仍不得采纳；记录原有效版本及拒绝证据，再做最小修正与复验。
