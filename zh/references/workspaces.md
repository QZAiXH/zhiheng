# 任务工作区

开发采用 Git worktree，规则由此处统一维护；规划、阅读和单纯诊断无需先建工作区。

- 先明确项目、目标分支、任务分支和本次交付范围。已有约定直接沿用；没有约定且有真实歧义才询问。新任务从目标分支创建独立 worktree，默认放在仓库旁，尊重项目布局。独立调用实现/调试也遵守本规则，但不因此获得提交或合并权限。
- 原工作区的未提交改动留在原处。任务依赖其中内容时明确包含范围与转移方式；不隐式 stash、搬运或覆盖，更不能把它们当作已存在于新 worktree。
- 确认所操作目录、分支与记录一致。非 Git 项目可继续调查；实际开发前明确建立仓库或选择已有仓库，不静默降级为原地开发。
- 使用项目工具链准备依赖。worktree 只隔离工作文件，不隔离端口、数据库、环境变量或外部服务；按实际需求配置，避免共享可写生成目录，不把密钥提交到仓库。
- 保留已跟踪、未跟踪、被忽略文件；忽略不等于可丢弃。清理前识别归属和是否可重建，只有确认可重建的本任务产物才可移除。有用内容保存或交接后再清理。不要用强制清理覆盖不确定性。

可用 [task.py 工具](task-tools.md) 创建和检查工作区及恢复记录。合并、整合检查与清理顺序由 [zh-finish](../../zh-finish/SKILL.md) 维护。
