# 委派、模型选择与独立上下文

主模型每次有意义的委派前，按需求清晰度、依赖和影响范围、推理难度、错误后果、验证能力、上下文与成本判断配置。文件数、行数和关键词不足以决定难度；审查也可能比实现难。

先从当前宿主工具声明或有效配置确认可用型号和推理档位。能力文档不能证明当前账号可调用。展示“步骤/角色、具体型号、推理强度、一句任务依据”，合并进计划；尊重用户全局、角色或步骤偏好，无需为已授权的常规模型选择再建确认流程。

| 工作特征 | 选择依据 |
| --- | --- |
| 明确机械改动或检索、结果易验证 | 选择能胜任的较快型号及受支持档位 |
| 常规功能、一般调试、明确跨模块改动 | 选择通用编码型号，中等或按需提高推理强度 |
| 架构、复杂状态、并发、难验证问题 | 更强推理能力及较高档位，同时改善边界和证据 |
| 独立验收 | 单独评估遗漏后果和验证难度，可以强于执行者 |

小任务主会话直接实现，无须为了换模型额外委派；外层规划默认当前会话。需要委派时使用实际的新会话，只提供相关范围与原始材料，不全量复制父历史。当前支持相应参数的宿主可传 `model`、`reasoning_effort`、`fork_turns="none"`；未来宿主以真实接口为准。不同 worktree 或同会话切换模型都不产生独立上下文。

启动时传入所推荐或用户覆盖的实际参数，记录任务与会话标识、请求值和可观察到的实际值。推荐文字不等于配置成功。指定配置不可用时说明限制并处理用户偏好/预算，不静默换型。失败先区分环境、需求、证据及推理原因，有依据才升级；不无限重试或一律最强模型。

独立验收的原始材料和上下文边界由 [zh-review](../../zh-review/SKILL.md) 维护。首次审查不能继承执行历史。返工复查可以沿用原审查会话，只补新候选、证据与必要决定，不导入执行者整段修复聊天。范围实质变化或审查上下文混乱时重新建审查会话。

同型号的新上下文可能仍犯相似错误，换型号也不是正确性保证。跨模型审查是可配置增强，不假定任意供应商可用，不默认增加额外审查调用。
