# 任务记录、交接与恢复

记录为易读 Markdown。在 Git 项目中，通过 `git rev-parse --path-format=absolute --git-common-dir` 定位公共 Git 目录，把活跃记录和大日志放入其 `zh/` 下；不要假定 `.git` 是目录。每个任务有独立 ID、记录及证据目录，不用全局唯一“当前任务”覆盖并行任务。工具生成的少量机器字段仅用于 Git 状态一致性，不要求用户编写。

下面的分支、worktree、候选及交付字段适用于开发任务；仅维护项目上下文时不为填字段启动开发流程。接入记录和非 Git 项目的保存位置遵循 [项目接入流程](../../zh-context/references/project-onboarding.md)，不存在的 Git 状态不编造。

最小记录：目标、范围和实际授权依据；验收条件；项目、目标/任务分支、worktree、基线与当前候选；约定的本地交付方式及远端边界；当前状态；原始证据指针；未决事项与下一步。多步骤任务再列依赖、已完成/进行中/阻塞，并区分开发、独立验收、提交合并、整合验证和清理状态。保存模型推荐依据、请求配置和工具可观察到的实际配置，无法观察的值明确标为请求值。

前端任务在同一记录中按需补充 [预览与确认依据](../../zh-implement/references/frontend-preview.md#记录与恢复)，不另建状态系统；恢复时区分原型版本、确认范围与正式候选，不能仅靠临时预览链接或最近一条反馈推断整个设计已获确认。

将已确认决定、尚未接受的建议和待定问题分开。决定有来源及理由，知识有来源、适用范围及核实时间。重要决定、已验收步骤、阻塞、交接后增量更新；不用等到上下文耗尽再总结。

交给执行者：本步骤目标与已授权范围、完整相关验收条件、工作区/分支/基线、必要项目规则、依赖及证据指针。执行者返回实际改动、检查命令/退出状态/结果、验收覆盖、阻塞或偏差、带来源的候选发现。未运行、环境阻塞、已有失败均不同于通过。由外层筛选发现，避免将执行者猜测直接提升为项目规范。

恢复时先读记录里的全部确认范围、决定及下一步，再核实实际 Git/worktree、目标和候选状态。检查是否已经合并、是否仍需整合验证或清理，避免重复合并。最新消息通常是对现有任务的补充；不悄悄替换计划、不重问已有决定，也不把建议变成用户确认。

保留既有 `.zhiheng/PROJECT.md`、知识与历史任务。需要共享的已验证知识和必要摘要才写入 `.zhiheng/` 或项目既有文档；引用实际提交与验证结果，不批量生成空模板。大日志保持本地，用户要求共享的证据另存持久路径。

旧任务迁移：保留原始记录与证据，从中恢复真实范围、授权及已完成步骤，核对现有代码后只安排剩余工作；新增恢复说明指回原记录。不重写历史结果，不恢复旧控制器或钩子。仅更新本任务明确拥有的入口，不扫描修改所有项目。
