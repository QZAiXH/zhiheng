# 需求讨论

由主 Agent 在用户会话中执行，保留用户决策及其理由。读取 [依赖配置](../double-loop/references/dependencies.md)，定位 grill-with-docs、grilling、domain-modeling 的上游入口和实际需要的引用。

1. 先探索事实：现有行为、调用链、接口、项目规范、测试入口，以及 GitHub/npm 是否已有成熟方案。事实由 Agent 查明；问题聚焦用户目标和取舍。
2. 分轮讨论当前可决定的关键问题，给出推荐选项。收敛到目标、受众、范围、约束、验收标准、兼容与失败行为；未证实假设显式标记。
3. 确认测试能观察的外部行为及必要验收证据，把上游规格阶段的测试边界确认提前到此处。关键术语沿用项目词汇；有长期意义的取舍保存为决策候选。
4. 保存中文需求摘要。尚无运行目录时使用总控登记的临时位置，创建运行后迁入持久记录。保存已确认事实与决策，不保存隐藏推理。
5. 交给总控动态推荐阶段配置，集中确认启动。用户已说“按这个做”且需求与配置均已明确时直接推进。

完成条件：范围和可检验验收条件明确，高影响问题已解决，需求确认可追溯。后续正常设计、拆分和测试反馈无需逐阶段审批。
