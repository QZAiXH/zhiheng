# 检查点恢复

读取 [运行协议](../double-loop/references/runtime.md)，定位用户指定运行；多个活动运行且无法判断时仅询问运行选择。

1. 先用 [dl-init](../dl-init/SKILL.md) 状态检查核对接入依赖与 Wiki reload 待办，再运行研发辅助脚本 resume，核对 Git 根、配置完整性、任务依赖、HEAD 和工作区内容指纹。返回就绪任务与版本漂移，不修改源码。
2. 检查存活 Agent、worktree、分支、交接和结果。先协调旧执行者，再重派任务，避免重复写入。
3. 沿用已确认矩阵，不重复配置确认；核对当前宿主能力。模型消失或能力变化时提出调整，不静默换模型。
4. 输入变化时重做受影响阶段，重新取得最终验收；记录旧检查为何失效。无法证明影响范围时从必要验证阶段恢复。
5. Wiki 通过现有 OpenWiki begin 接续其自己的队列，不自行清理内部状态。交付前核查远端和 PR，清理前重新检查文件与保留引用。
6. 保存恢复结果，由 double-loop 推进。缺少外部条件时记录阻塞并继续独立工作。

完成条件：有效状态明确，过期证据已标记，下一工序可追踪。已 complete 的运行只报告结果，不重复发布。
