# 方案与任务拆分

总控按 [调度契约](../double-loop/references/models.md) 启动设计角色的新上下文。接收确认后的需求、源代码指针、规范与相关 ADR；按 [依赖配置](../double-loop/references/dependencies.md) 读取 to-spec、to-tickets，按需读取 research、codebase-design。

1. 从代码和项目清单确定现状，优先复用成熟组件。具体架构或依赖疑问才触发 OpenWiki 查询，并核对当前源码。
2. 生成中文规格：问题、预期行为、用户故事、接口和数据变化、关键决策、测试策略、不做事项。解决实现者无法自行合理决定的契约，避免锁死无意义细节。
3. 交给 [dl-review](../dl-review/SKILL.md) 使用审查角色独立检查设计。根据发现修订；范围变化交总控处理，普通方案缺陷直接修正。
4. 方案通过后拆成完整纵向任务，每任务包含行为、验收标准、必要代码指针与真实前置依赖。大范围重构采用扩展 → 分批迁移 → 收缩，各批验收承诺明确。
5. 默认以运行目录的一任务一文件作本地跟踪；已有项目跟踪规则则沿用。创建远端 Issue 需已有明确授权。依赖图写入检查点，脚本拒绝重复 ID、缺失依赖和循环依赖。

适配：读取上游方法，不把手动技能串成自动调用。不重复请求测试边界、拆分粒度和发布确认；实质新取舍才升级。

完成条件：规格通过独立审查，每任务可验证且能装入独立上下文，依赖图有效，下一批就绪任务明确。按 [运行协议](../double-loop/references/runtime.md) 交接。
