# 独立审查与验收

按 [调度契约](../double-loop/references/models.md) 使用本次审查角色，读取 [运行协议](../double-loop/references/runtime.md)。代码审查按 [依赖配置](../double-loop/references/dependencies.md) 读取 code-review 和所需引用。

## 设计检查

独立读取需求和方案，检查验收可检验性、接口与数据契约、失败行为、依赖、兼容和范围。报告缺项、错误假设与不可执行任务；普通问题交设计角色修订。

## 代码检查

1. 从记录取得固定基准和目标提交，确认引用有效。提交差异用 git diff <base>...<target>；未提交修复另外检查暂存区和工作区，不能因 HEAD 未变漏审。
2. 运行项目实际测试、类型、Lint、构建或必要 E2E。记录命令、退出码、目标版本和证据位置。工具不存在时明确缺口。
3. Standards 与 Spec 两轴分别用审查模型的新上下文：前者接收规范、差异与上游启发式；后者接收需求、规格、验收条件和差异。两轴不共享结论，额度不足则依次执行。
4. 发现包含位置、依据、影响和复现方法，区分阻塞错误与判断性建议。机械规则交工具，项目规范优先于通用启发式。
5. 交实现或设计角色修复；用新审查上下文复查，运行受影响验证。集成验收覆盖任务之间的关系。

验收不能只用实现者新增测试：从需求独立构造关键成功、失败、边界和回归场景，以真实调用、现有接口或独立验收用例补足证据。

完成条件：目标版本明确，各轴无未解决阻塞发现，必要检查真实完成。源码变化使旧结论失效，不能以陈旧证据推进交付。
