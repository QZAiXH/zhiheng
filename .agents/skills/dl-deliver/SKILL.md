# 交付与清理

按 [运行协议](../double-loop/references/runtime.md) 读取任务状态与验收证据，按 [依赖配置](../double-loop/references/dependencies.md) 读取 pr 作为描述方法。Git 和 GitHub CLI 执行实际提交与发布。

1. 确认所有任务已集成，独立验收覆盖最终代码，知识维护完成或无需更新，保留资料引用有效。核对最终差异、目标分支与提交规范。
2. 保存完成摘要、规格与验收证据到持久位置。检查 .workflow 暂存材料不会进入提交；用精确文件列表暂存。
3. 按已有授权提交和推送。适用项目规则要求额外提交流程则执行，不调用无关的全局工作流。缺少 Git 身份、远端或权限时保存状态并报告阻塞。
4. 先核查分支已有 PR，再创建或更新，避免重试重复发布。中文描述说明问题、结果、验证与实际限制；默认不合并、部署、发版或提前关闭待合并 Issue。
5. 核实远端提交和 PR 链接，保存交付结果。按 [清理规则](references/cleanup.md) 生成预览，在同一授权范围内执行可清理项，记录暂缓项。

清理完成条件：登记且内容未变的临时文件已删除，规范、证据、最小运行记录和 PR 分支可访问；暂缓项有理由与下一步。未完成工作保留恢复材料。
