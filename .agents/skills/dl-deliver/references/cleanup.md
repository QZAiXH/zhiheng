# 完成后的清理

先提炼 → 核验稳定目标和引用 → 提交并核实 PR → 预览 → 清理 → 保存结果。用户启动本流程已授权清理本次拥有且无保留用途的临时材料，不逐文件请求批准。

## 保留与删除

自动删除：scratch 中提前登记并封存、内容未变化的临时草稿、废弃交接、重复日志和临时复现文件。需要知识提炼的草稿在登记或封存时填写 extract_to，列明稳定 Wiki/测试/ADR 位置；普通无价值草稿无需编造提炼目标。

保留：需求和规格原件、ADR、独立验收证据、被交付记录引用的截图或录屏、模型矩阵、完成摘要、最新检查点、清理记录、PR 分支、未解决问题的复现材料。默认终点只是创建 PR，尚未合并的资料不能当作已经完成长期归档。

辅助脚本只删除本次 scratch 中单个文件，不递归删除目录，不扫描认领未知文件，不删缓存、用户既有文件、OpenWiki 内部状态、任务分支或远端内容。临时 worktree 和外部登记产物由总控单独检查。

## 文件门槛

1. 文件创建前 register，写入后 seal；已存在文件不能补登记为本流程新建。登记并不证明可删。
2. 全部任务 done；验收 passed；OpenWiki complete 或有依据的 noop；真实 PR 已创建；交付提交存在且与当前 HEAD 一致。
3. 保留文件与证据存在，替代路径不在临时目录，替代内容已核验。Wiki/Claims 的证据不能只指向待删草稿。
4. 文件为普通文件，路径与父目录无符号链接，范围局限本次 scratch，内容 SHA-256 与封存记录相同。
5. 所有保留 Markdown 的普通链接、引用式链接、图片、HTML 和 repo:// 引用均不得依赖该文件。脚本用 CommonMark 解析器检查，包括平衡括号、编码路径和绝对文件路径；Agent 另查代码、配置及动态引用。仓库内文档符号链接可只读核验；无法核对的文档返回逐项暂缓及原因，不继续删除。迁移证据与更新引用后重新核验。

先运行 cleanup 预览。确认所有 Agent 停止写这些材料、额外引用检查完成后运行 cleanup --apply。脚本写入删除意图再 unlink，中断后可重试；缺失且有删除意图的文件记录为已删除，内容变化的文件暂缓。保存删项与留项原因，不通过修改分类绕过失败门槛。

## Worktree

从总控登记的路径逐个核对 Git common-dir、任务分支和本次所有权。确认工作区干净、无未跟踪成果、任务提交可从已推送的集成提交到达，且无活跃 Agent，才使用 git worktree remove。保留 PR 分支；工作区脏或归属不明则保留并记录。不得使用强制移除或批量 rm 替代 Git 核验。

## 未完成与恢复

阻塞、验收失败或 Wiki 未完成时保留必要材料。清理暂缓不自动取消已成功的 PR 交付，最终报告具体留项。complete 可以包含有明确理由的暂缓清理项；恢复只重试仍符合门槛的项，不扩大范围。
