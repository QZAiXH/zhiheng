# 双层循环总控

主 Agent 保留用户讨论，负责外层 Plan → Do → Check → Act；实现与审查交给独立子 Agent。用户确认需求和本次执行配置后，连续推进至创建 PR 和完成清理。所有正文、规格和交付说明使用中文。

## 开始

1. 定位目标项目，读取适用项目指令、现有规范和任务记录。本包只提供编排技能；开发工作在目标项目执行，不能把技能包目录误作业务项目。
2. 用 [dl-init](../dl-init/SKILL.md) 的 status 核对接入。首次使用或依赖变化时按 [依赖配置](references/dependencies.md) 接入；已有效则跳过安装。需求尚未讨论时先完成初始化的本地准备，Wiki Host 选择并入下一次集中确认，再完成 Wiki 接入。缺少写入或原生调度能力时保存具体缺项，继续独立的需求探索。不要改用 harness-workflow。
3. 通过 [dl-discover](../dl-discover/SKILL.md) 确认需求。已有完整讨论可直接整理，避免重复采访。
4. 按 [动态模型推荐与调度](references/models.md) 生成本次矩阵。合并展示需求结论、模型、强度、上下文、并发数、首次 Wiki Host（需要时）和交付终点，集中确认一次。此前的有效授权可沿用，不能把沉默当作确认。
5. 完成待办 Wiki 接入并核对 Git 基线，再按 [运行协议](references/runtime.md) 创建记录。读取 [流程图](references/workflow.md)，依阶段调用本包技能；上游方法按阶段读取，不预载全部依赖和 Wiki。

## 推进

- Plan：dl-plan 形成规格，dl-review 独立审查设计，设计角色修订；通过后形成并校验任务依赖。
- Do：dl-execute 调度就绪任务，每任务执行实现 → 工具反馈 → 独立审查 → 修复 → 复审；通过并集成后才释放依赖。
- Check：dl-review 在集成版本完成整体验收。失败回到修复；影响范围或架构的结果交总控调整计划。
- Act：dl-knowledge 固化已验证机制与决策；dl-deliver 提交、推送、创建 PR，然后按清单清理。

普通测试失败、可复现缺陷和可安全解决的冲突自主处理。范围变化、关键业务取舍、用户才能提供的条件或宿主能力不足时，携证据、影响、选项和推荐方案询问。同类失败连续三次且无新证据时保存检查点并升级，不能机械重试。继续不受阻塞影响的任务；定期报告关键进展。

## 完成条件

所有任务已通过并集成；独立验收对应最终代码；知识维护完成或确认无需更新；PR 已创建且提交可追踪；清理已执行或具体暂缓项已记录。默认不自动合并、部署、发版或关闭尚待合并的 Issue。

中断后通过 [dl-resume](../dl-resume/SKILL.md) 恢复。辅助脚本只校验与保存状态，不证明模型实际调用、测试真实通过或外部发布成功。
