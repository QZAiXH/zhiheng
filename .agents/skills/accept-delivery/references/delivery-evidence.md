# Delivery evidence and cleanup

Use the original tracker record and its linked parent or children as the entry point. Preserve each required original report, command output, reproducer, dispatch record and unique failure artifact. Keep the link with its tested or reviewed revision and the check it supports. Preserve original bytes when relocating evidence.

1. **Before releasing a work area**, put any unique original needed for acceptance, recovery or an agreed retrospective in a durable tracker attachment, Git revision or project evidence archive. A formal local tracker can keep evidence alongside its ticket using relative paths. Preserve the link layout in portable archives. Update the tracker pointers and verify each final copy against the source, using a digest for relocated files when practical.
2. **At the development handoff and before recording acceptance**, start at the original ticket and open every required original from its final pointer, including separate review reports when due, linked handoffs and any child evidence used by the parent. Verify that it covers the cited revision and criterion. Record a missing path or attachment by name and keep the affected ticket open until its evidence can be verified.
3. For a writable delivery, use the release procedure below at the requested stopping point. Report-only uses read-only access and returns the report with any evidence gaps.
4. Reopen a closed ticket to verify its recorded status and evidence.

## Release task worktrees

The coordinator, or the current session in a direct delivery, releases worktrees recorded as created for this task. For completion, run after acceptance and any required delivery checks pass, before closing the ticket. For development only, run after the local commit, required review and development handoff are recorded, and keep the ticket open. Report-only leaves delivery worktrees and tracker records in place.

1. Reopen the original ticket and any linked parent or child, then open the final delivery commit, raw test results and required review reports using their recorded pointers. Confirm that the ticket and its links can be opened from a retained location. For local Markdown, resolve the current canonical ticket, linked records and relative evidence paths and verify they are outside the removal set. If the checkout holds the only current copy, keep it until the full record and links have verified durable locations. Preserve unique originals and pending synchronization bodies under the rules above.
2. From a checkout or Git directory that will survive cleanup, check `git worktree list --porcelain` against the task's recorded absolute path, branch and current commit. Verify that the retained local branch ref resolves to the expected commit and can reach the delivery commit it carries. Confirm the worktree has no active writer, lock or unfinished Git operation. Inspect the candidate with `git -C "$worktree" status --porcelain=v1 --untracked-files=all --ignored=traditional --ignore-submodules=none`. Keep staged, unstaged, untracked and ignored work that is unsaved or of uncertain ownership. Check ignored content for local tickets, evidence and unsaved files. Inspect any paths hidden by custom index flags before removal. For any retained worktree, record the path, branch, current commit, reason and next recovery action.
3. Remove only an eligible linked worktree by its exact path using `git worktree remove "$worktree"` from the surviving repository location. Keep the local branch. If Git refuses removal, retain the checkout and record the actual error. A retry starts with the recorded path and branch and treats an already absent, unregistered path as released only after the post-cleanup checks.
4. Verify that the removed path and registration are both gone, the local branch still resolves to the expected commit, and the recorded delivery commit can still be opened. Start again at the original ticket and reopen the same test, review, parent and child pointers. Record removal or retention and the verified evidence locations before closure or the final development report.
