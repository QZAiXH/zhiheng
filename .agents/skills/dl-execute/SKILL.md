# 任务实现

读取 [运行协议](../double-loop/references/runtime.md) 和 [调度契约](../double-loop/references/models.md)，按 [依赖配置](../double-loop/references/dependencies.md) 读取 implement-spec、tdd；失败时读取 diagnosing-bugs。

1. 选取前置任务均 done 的就绪任务。总控建立集成分支，以当前集成提交创建本次拥有的独立 worktree 和任务分支，记录路径、提交及所有权。保留用户已有变更。
2. 启动实现角色：显式使用确认后的模型与强度，新上下文只携任务、规格片段、代码指针、适用规范和接口。按需补充事实；接近上下文预算时保存进度后换新 Agent。
3. 以已有公共测试边界执行红 → 绿；无需测试的低影响改动运行合适检查。断言面向行为，避免镜像实现。
4. 失败时建立复现、依据反馈定位原因、修复并加入必要回归检查。调试进展直接报告，不等待用户认可每个假设。
5. 使用 [dl-review](../dl-review/SKILL.md) 进行工具检查和独立双轴审查。修复后重新检查和复审，不能以实现者自评替代。
6. 同步集成分支最新提交。同步或合并改变待审代码时重新验证；总控串行协调集成。done 表示已验证、已审查、已集成，才可释放依赖。

并发须给审查留下线程额度，额度不足则串行审查。只有总控写检查点和清理清单，子 Agent 通过交接文件报告。

完成条件：任务验收通过，审查无阻塞问题，成果进入集成分支并记录提交。全部任务完成后运行整体验收；临时 worktree 保留至交付阶段核验清理。
