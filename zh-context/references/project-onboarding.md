# 项目接入与重复刷新

在用户明确要求建立或保存项目上下文时读取。写入与操作授权边界见 [zh-context](../SKILL.md)；只读请求不执行文档维护。

## 从已有项目建立上下文

1. **检查已有状态**：读取适用 `AGENTS.md`、现有文档、`.zhiheng/` 和相关旧任务；是 Git 项目时核对 Git 状态。识别有效资料、过时指针和知识缺口，保留原工作区改动。现有文档含用户未提交内容时，只做可明确归属本次接入的增量维护，不能整体覆盖或回退。
2. **说明范围**：简要展示拟调查、保存或更新的内容。默认覆盖主要模块和入口，再按当前任务深入；小而明确且已授权的接入直接继续，复杂或有关键未决事项时沿用已有计划确认方式。无需为上下文文档接入创建开发 worktree。
3. **核实知识**：追踪相关代码和配置以确认模块职责、调用关系、工具链、启动和检查命令，记录事实来源及实际覆盖范围。文件清单不等于读完源码。命令区分“配置声明”“实际通过”“失败”“环境阻塞”，保留执行依据或未运行原因；运行条件不足时记录限制，不为了填满状态自动安装依赖或配置外部服务。
4. **保存最小上下文**：优先更新或引用项目已有文档；缺少稳定知识入口时创建 `.zhiheng/PROJECT.md`，保存项目地图、来源指针、命令状态、未核实事项。已有有效入口时复用，不因路径不同复制一份知识正文。只有出现已验证的术语、决策或来源信息才按需补充相应内容，不预建空文件或批量模板。
5. **建立入口指针**：需要时在 `AGENTS.md` 增加简短、可定位的上下文索引，保留已有规则和用户内容；已有有效入口就复用。不存在 `AGENTS.md` 且确需入口时仅写必要指针，不附加新的通用开发约束。只更新确认归属的旧指针，不顺带改全局设置、其他技能或不相关项目。
6. **检查并回传**：核对入口可定位、地图有代码/配置依据、命令状态与证据一致、知识缺口仍清晰可见。报告覆盖模块、保存或更新的文件、命令状态、旧资料处理和下一步。关键事实无法核实时标为部分接入，不虚报全库梳理完成。

## 重复接入与旧资料

再次接入先读已有覆盖和缺口，只刷新缺失、过时或受当前任务影响的部分；避免重复全库调查、重复 `AGENTS.md` 指针和重复文档结构。保留用户记录，知识正文只在一处维护。

复用旧 `.zhiheng/` 中有效知识；文档与代码矛盾时指出差异和依据，再修正受影响的当前事实。只整理已确认归属的旧入口，保留历史任务和原始证据，不把历史记录改写为当前规则。未完成任务先核对实际状态并记录剩余工作；接入本身不授权恢复产品开发，也不重新启用旧 controller 或钩子。

跨会话接入增量保存覆盖范围、确认决定、未决事项和下一步，复用 [任务记录规则](../../zh/references/records.md)。Git 项目可将确需的活跃接入记录放在公共 Git 目录的 `zh/` 下；不为记录而创建开发任务分支或 worktree。非 Git 项目把必要的接入进度保存在已授权的上下文文档中，避免另建一套任务状态。简短只读调查直接回传即可。
